# TL-MR6400 EU V5: dedicated Ethernet backup audit

Audit date: 2026-10-21. Hardware is **V5.0**, not V5.20/V5.30. This records
the stock-firmware configuration and its limits; it is not a claim that the
router is fully hardened or that automatic Freebox takeover is armed.

The audit visited all 43 unique non-message Advanced pages, plus the log
configuration and SMS settings. SMS contents were not inspected, USSD commands
were not sent, and no cloud account was linked. Before/after configuration
backups, detailed settings and certificate information stay in a private local
directory, not in this public repository.

## Dedicated gateway configuration

| Area | Setting / decision | Reason |
| --- | --- | --- |
| Operating mode | 3G/4G router, cellular upstream | Never use the Freebox as the backup's upstream. |
| LAN | Static `192.168.1.253/24` in this deployment | Checked against the primary DHCP pool, reservations, known hosts and live ARP replies. |
| Wiring | A LAN port to the Freebox LAN | No second client network or change to client gateways. |
| DHCP server / relay | Off | Only the Freebox supplies ordinary client addressing. |
| Second LAN IP | Off | Avoid unnecessary addresses and ambiguity. |
| LAN IPv6 RA / DHCPv6 / RDNSS / ULA | Off | Do not introduce an additional IPv6 router. |
| IPv6 tunnel | Off | No 6to4/tunnel fallback. |
| NAT / mobile data | On | Required for the IPv4 backup data path. |
| Network mode | 4G preferred | Allows a usable 3G fallback rather than making LTE-only a new failure mode. |
| Operator / LTE bands | Automatic | No carrier or band lock that would impair roaming or future SIM changes. |
| APN / authentication / PDP type | Working operator-selected profile | Do not replace a working profile with guessed APNs or force all future carriers to IPv4-only. |
| Carrier DNS | Automatic, no override | Follow the SIM/operator. |
| Failover DNS | Router DNS proxy at `192.168.1.253` | Public UDP resolvers timed out on the tested roaming service; the proxy passed UDP and TCP DNS. |
| Roaming | On for the currently authorized roaming test | Reassess costs and policy whenever changing SIM/plan. |
| Data cap | Off for the authorized test | Avoid a stale allowance silently disabling backup service. |
| Monthly cellular usage counter | Retained | Useful even with per-device traffic monitoring disabled. |
| MTU | Existing modem/firmware value, 1500 | No arbitrary reduction or unsupported modem tuning. Validate real traffic before changing it. |
| Wi-Fi / guest Wi-Fi / WPS PIN | Off | This device has an Ethernet-only job. |
| Wireless schedules / night mode | Off | Do not add scheduling surprises; keep status LEDs useful. |
| UPnP port mappings | Off, mapping list empty | No unsolicited automatic port openings. A separate LAN listener remains; see below. |
| DMZ / virtual servers / port triggers | Off / empty | No incoming service exposure is required. |
| IPv4 SPI / IPv6 firewall | On | Retain stateful filtering; disabling IPv6 advertisements does not justify disabling its firewall. |
| Fixed-threshold DoS filtering | Off | Avoid misclassifying aggregated VM traffic as a single abusive LAN client. |
| Parental / service / MAC access restrictions | Inactive, no blocking rules | Avoid hidden policy breaking selected clients during an outage. |
| IP/MAC binding | Off | No stale or conflicting binding with gateway impersonation. |
| QoS | Off | No unsupported fixed bandwidth assumptions for a variable cellular connection. |
| Per-device traffic monitor | Off | Unneeded tracking; forwarded household traffic is masqueraded behind the VM anyway. No CPU gain was quantified. |
| FTP / TFTP / H323 / SIP / RTSP ALG | Off | Avoid unnecessary protocol helpers and payload rewriting in this dedicated gateway. |
| PPTP / L2TP / IPsec pass-through | Retained | Do not gratuitously break outbound VPN compatibility. |
| OpenVPN / PPTP VPN servers | Off, no connections | This router is not the remote-access server. |
| DDNS / TP-Link cloud | Not configured | No additional public/cloud management dependency. |
| CWMP/TR-069 / SNMP | Off | No operator management or SNMP agent is needed here. |
| WAN web management, HTTP and HTTPS | Both off | LAN-only administration. This is not an external scan of every WAN-bound daemon. |
| Local HTTPS | On, TLS 1.2 verified | Encrypt local administration, with important certificate limitations below. |
| Local HTTP | Retained as stock recovery fallback | Plain HTTP remains a residual LAN management exposure. |
| Local / remote ICMP | Local on, remote off | Preserve local diagnostics without enabling remote ping. |
| Clock / NTP | UTC, two NTP servers | Avoid DST ambiguity; time returned correctly after restart. |
| Local system log | On, Information level | Keep useful event history without enabling Debug logging. |
| Remote syslog | Off | No receiver has been deliberately provisioned yet. |
| Reboot schedule | Off | No daily reboot that could interrupt a real outage. |
| SMS service center | Existing setting retained | Do not replace it with a guessed number or send chargeable messages. |

Disabling ALGs is a deliberate compatibility trade-off: legacy active FTP,
TFTP or some older voice/video applications may require a specific helper to
be restored after a real application test. Ordinary web and DNS tests do not
prove every VPN, voice or legacy application works.

## Firmware and management limitations

The installed stock release is `1.3.0 Build 201207 Rel.56223n`, matching the
latest firmware listed for this exact EU V5.0 on the
[French manufacturer support page](https://www.tp-link.com/fr/support/download/tl-mr6400/v5/)
at the audit date. This is an old release, not evidence of ongoing security
maintenance. The ISP/APN database is a separate component. A later ISP file
exists, but its published change is unrelated to the working profile and the
manufacturer warns that ISP databases cannot be downgraded. It was not flashed
merely to make a version number newer.

Actual LAN TCP connections found SSH/22, Telnet/23 and a UPnP SDK HTTP listener
on 1900, in addition to DNS and web administration. SSH advertised Dropbear
2017.75; the 1900 listener advertised UPnP SDK 1.6.19. The UPnP configuration
really was disabled, so the checkbox does **not** prove all related listeners
are stopped. No supported UI disable controls for these remaining listeners
were identified. Do not call them disabled, infer their WAN exposure from a
LAN scan, or use undocumented configuration writes to guess at disabling them.

The local HTTPS endpoint negotiated TLS 1.2, but its certificate uses a
**1024-bit RSA key**. Modern Python/OpenSSL verification rejects that weak key
even with the device CA supplied. Its leaf certificate also changed around the
reboot/WAN-address change, and includes the WAN address in its subject alternate
names. Leaf-fingerprint persistence must not be assumed. No OS trust store was
changed and no global certificate-verification exception was installed.

The supplied administrator password was not silently rotated. Replace it with
a unique strong password using an agreed secure handoff before permanent use.
Keep this router on a trusted LAN; settings alone do not provide a separate
management security boundary.

Manufacturer notices checked for
[V5.3 Telnet](https://www.tp-link.com/us/support/faq/5016/),
[V7 web management](https://www.tp-link.com/us/support/faq/5259/) and
[V8 VPN/file handling](https://www.tp-link.com/uk/support/faq/5292/)
name different hardware revisions. They are not proof of either vulnerability
or safety for this V5.0, and their firmware images must not be cross-flashed.

## Validation and boundaries

- Saved pre-change, post-change and verified post-reboot configuration backups.
- Authenticated over local HTTPS and checked the actual settings model.
- Rebooted the router and checked persistence of addressing, DHCP/IPv6 shutdown,
  ALGs, traffic monitoring, firewalls, management restrictions and roaming.
- Tested explicitly marked VM traffic through the backup gateway, not the
  normal Freebox route: TCP health probes, UDP/TCP DNS and verified HTTPS.
- Downloaded 1 MiB over verified HTTPS through that marked route after reboot:
  1.24 seconds including connection setup, approximately 6.75 Mbps for this
  small transfer. This is a smoke test, not a full throughput benchmark.
- Temporary policy routes are removed afterward; normal fibre traffic and the
  monitor-only daemon keep their existing routing and safeguards.
- Real controlled household failover/failback, application coverage and Freebox
  LAN IPv6 handling remain separate work. This audit does not arm takeover.

There is no stock setting that can add missing radio bands, improve antenna
placement remotely or guarantee roaming-carrier performance. Do not lock a
band or carrier based only on signal bars.

## If stock firmware is not enough

The residual services and weak HTTPS certificate give a concrete reason to
consider OpenWrt or a separate management/network isolation design before
permanent deployment. They are not reasons to flash speculatively mid-audit.
The [official OpenWrt V5 device page](https://openwrt.org/toh/tp-link/tl-mr6400_v5)
documents 8 MiB flash, 64 MiB RAM and first installation via TFTP, not the OEM
web uploader. A migration needs a minimal exact-hardware image, cellular/DNS
configuration, recovery preparation and a full repeat of the live tests.
